## What the platform API can identify

The macOS 15.5 SDK exposes `IOPCIDevice::getBusNumber()`, `getDeviceNumber()`, and `getFunctionNumber()` (`IOPCIDevice.h:583-602`). Candidate 0.44.93 now captures vendor/device/subsystem IDs plus BDF in `Cx3Mlx4::start`, adds a fail-closed `Mlx4Hw::readPciIdentity()` adapter, and compares the tuple against the starting provider before and after platform FLR (`src/Cx3Mlx4.cpp`, `src/Mlx4Hw.cpp`, `src/flr.inc`, `src/mlx4_pure.h`). Synthetic tests cover null/invalid reads, start-identity mismatch, and post-reset drift. This detects provider/function identity changes during one live instance; it is not a unique reset epoch or proof that DMA stopped. The successful post-reset comparison still leaves all owner/poison latches set and performs no old-MMIO access or release.

The public `IOPCIDevice::reset(FunctionReset, OptionNone)` documentation says the call blocks until link/device is usable and, for a multi-function device, resets all associated functions (`IOPCIDevice.h:1095-1110`). The reset entry therefore has a wider possible effect than the one provider object's current command gate. The driver tracks a single PCI provider and one `IOEthernetInterface`; its Ethernet path programs physical port 1 (`Cx3Mlx4.cpp:4630, 5642-5863`). It has no coordinated state machine for port 2 or sibling PCI functions. A sibling list cannot be inferred merely from the current function's BDF. Registry parent/child accessors exist, but their presence does not establish a complete set of functions in the reset domain.

## UAR / doorbell and callback boundary (2026-10-23)

The normal path uses two MMIO doorbell classes through the mapped BAR2 view: EQ consumer-index writes use the EQ's computed `fEqDoorbell` (`Mlx4Hw::eqSetConsumerIndex`), while CQ arm and SQ send writes use the shared runtime UAR index (`cqRingDoorbell` / `sqRingSendDoorbell`). The CQ and QP contexts carry that same runtime UAR index; the EQ doorbell address is derived from its EQ number. These are MMIO locations, not independent DMA allocations: their safe lifetime follows the EQ/CQ/QP owner and BAR2 mapping, and there is no standalone UAR `free` in this port. The writers validate that BAR2 is mapped and the offset stays inside the 8 MiB window, but these range checks do not establish that an owner is still live.

The EQ writes have selector and IRQ sources. IRQ drainage has a source-level API contract: this implementation uses `IOInterruptEventSource` (not the filter subclass); the local SDK header says its actions are delivered in a guaranteed single-threaded manner, with only one action executing in a workloop event chain (`IOInterruptEventSource.h:48-51`). `IOWorkLoop` is documented as single-threaded hardware access (`IOWorkLoop.h:51-55`), and successful `removeEventSource()` does not return until the workloop acknowledges removal and releases its retained source reference (`IOWorkLoop.h:246-251`). Together these contracts support the inference that a successful removal drains this source's action before `irqReleaseObjects()` releases its local reference and `stop()` proceeds to `teardownEq()`. The removal-failure path retains the source and all dependent owners. This is stronger than a cumulative callback counter, but remains a documented SDK contract/inference: the host harness and target-kernel runtime do not independently exercise the workloop implementation. CQ-arm diagnostic writes are in selectors. The normal TX send doorbell has an additional stack-thread source: `outputPacket()` writes the send doorbell outside the user-client transaction lock. The previous slice added `Mlx4TxAdmissionGate`: close bit and active count share one CAS word; `outputPacket()` attempts admission before any TX-state read and uses an RAII leave on every admitted path. The current slice transfers all attached/late-orphan interface references to a dedicated thread_call which invokes `detachInterface(..., true)` away from the stop/selector/workloop context. `stop()` gives this synchronous family termination a 2,000 ms deadline and pins self/provider plus all dependencies if it times out or the worker cannot self-free. After the family barrier returns, stop verifies the admission count is drained, then `netServiceStop()` takes `fNetTxLock` around in-flight mbuf accounting and ring release. `test-net-stop-tx-drain.py` checks 13 source contracts; `test-net-detach-worker.py` executes the production helper/worker in eight host cases, including already-pending submission, missing worker, timeout and call-free failure; `test-tx-admission-gate.py` runs a 100-round, eight-thread CAS race stress test.

This remains a partial fence. The local SDK contract (`IONetworkController.h:1288-1302`) says `sync=true` terminates the interface synchronously and the interface detaches from its controller after the data link layer removes references to interface-exposed structures; it warns this may block for an indeterminate duration. The implementation isolates that call in a retained worker and bounds only the stop thread's wait; timeout preserves the complete teardown transaction. A host harness covers transferred references and timeout/free-failure behavior, but does not execute the real networking family or prove this API's runtime behavior on the target kernel. IRQ action removal is supported by the documented single-threaded workloop contract above. Timer drainage now has a separate software gate: `netTimerAction()` must enter the same atomic admission counter that `stop()` closes and waits to drain before timer/resource teardown; a queued callback arriving after close cannot call `netTick()`. The XNU implementation for the running kernel (`xnu-11417.140.69`, `IOTimerEventSource.cpp`) also routes the no-options constructor to `PriorityKernelHigh` and makes `cancelTimeout()` use `thread_call_cancel_wait()` for an active callout. Source/model checks support this lifecycle, but the target runtime was not exercised. Neither family termination nor callback drainage proves device DMA quiescence, reset-domain scope, or a release credential. Therefore R02/R03/R06 remain open and the runtime UAR/BAR2 view is not cleared for release.

The exceptional `thread_call_enter()==TRUE` return means the work item was already pending, so this invocation did not enqueue a second callback. The helper had already taken a new self-reference and staged the interface references for the pending worker; the old branch left the new self-reference unmatched and left stale interface fields behind. The regression test models one prior queued worker reference, exercises the real extracted production helper, and verifies that the pending worker consumes the staged interface refs while the current submission releases only its surplus self-reference. The test failed three assertions before the production change and passed afterward. This establishes the local refcount/field-transfer behavior for the documented API return value; it does not establish that the branch was observed on the live kernel.

## Minimum truthful model

1. A provider-local device identity should include vendor/device/subsystem IDs plus BDF, captured at `start` and re-read before/after platform reset. Identity mismatch means `UnknownRetained`; it cannot advance the generation or release anything.
2. A monotonic, checked provider-local generation may distinguish host bookkeeping before and after an attempted reset. Increment it before the first reset operation that could affect the device; overflow or missing identity is a permanent fail-closed state. Stamp every device-owned allocation/ledger entry at the point ownership is transferred, not only at allocation.
3. A reset result must carry the exact identity, old/new generation, and an explicitly enumerated reset-domain scope. Unknown sibling/port scope cannot set `scopeAccounted`. Platform Success and a generation increment are observations, not release credentials.
4. A resource may transition `DeviceOwned(g)` to `Returned(g)` only after independent evidence that its particular DMA owner is quiescent, the CPU/workloop/IRQ callbacks that can touch it are drained, bus mastering is disabled and verified after platform config restore, and the reset domain accounts for every affected function/port. Otherwise retain it as `UnknownRetained`; do not free or repurpose it.
5. The credentials and generation tags must be consumed by the actual release sites (`freeIcmTables`, QP/CQ/MR teardown, quarantine drain, mailbox release), under the same admission/transaction boundary. A diagnostic-only counter or ABI field does not change lifecycle behavior.

## Implementation boundary and next gate

The source-level MTT allocation/release inventory is recorded in [r06-mtt-owner-inventory.md](r06-mtt-owner-inventory.md). The `.103` CQ/EQ timeout-owner gap, `.105` EQ create-rollback refusal gap, `.106/.107` ordinary queue create-rollback owner reachability, and `.108` bounded A/B dummy reservation have offline fixes and regression coverage. Next offline slice: finish the release-site/callback inventory for experimental queue paths and connect per-owner normal-return evidence to real free sites; do not promote generation stamps or `HW2SW_*` result booleans into a generic credential without establishing each command's DMA semantics and CPU callback exclusion. Timer callback drainage remains unproven; IRQ action drainage is supported by the local SDK's single-threaded action and synchronous removal contracts but is not target-runtime tested. Any eventual typed release credential must be produced only from independently validated evidence, then consumed by actual direct frees and retained-ledger drains. Until independent DMA quiescence and complete reset scope are established, potentially device-owned memory must remain retained. Before any hardware FLR, determine from real IORegistry/PCI configuration whether this card presents other functions and whether both physical ports share this reset/driver lifecycle; configure a policy that refuses FLR if that scope cannot be enumerated and coordinated. The public API documentation and current source do not prove these hardware facts.

No claim is made that this explains the historical freezes, that macOS executed every Linux TRPND/readiness step internally, or that the current device is safely recoverable. P0/P1 and R06 remain open.
