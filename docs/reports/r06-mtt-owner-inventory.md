UAR/doorbell source inventory: this implementation has no dynamic UAR allocator/free pair. `reservedUarStart()` derives the first general-purpose UAR index from `INIT_HCA.uar_page_sz` and `QUERY_DEV_CAP.reserved_uars`, with the mlx4 rule reserving the first 128 UARs for EQ doorbells. The driver reuses one runtime UAR index (`fR4CqUarStart`) across its RX/TX CQ and QP contexts; EQ doorbells are address-derived from EQN. CQ, SQ, and EQ doorbell helpers issue BAR2 MMIO stores through the shared `fMap2/fReg2` mapping. Thus there is no per-doorbell heap object to free: the relevant lifetime owners are the queue/EQ objects, callback/IRQ paths that may ring them, and the BAR2 mapping released by `Mlx4Hw::shutdown()`. The normal stop sequence closes admission/drains selectors and TX callbacks, releases IRQ objects, returns/tears down EQ and QP/CQ/RQ owners, disables new PCI bus mastering (explicitly not a flush), then shuts down/unmaps BAR2. Incomplete early-stop paths intentionally return before this sequence. Remaining proof: every caller/callback is excluded before the last BAR2 store and device/IRQ semantics are independently established; source ordering and synthetic tests are not hardware proof.

## Findings

The allocator tracks exact live `(offset, pages)` ranges and rejects partial, duplicate, and untracked frees. This inventory began before MTT ranges were tied to concrete DMA allocations; the current state is recorded below. Neither owner identity nor generation proves that DMA/CPU/IRQ access is quiescent.

## Evidence boundaries and next work

- Source search found four regular `Mlx4Hw::mttAlloc()` production functions (`cqCreate`, `rqCreate`, `sqCreate`, `eqCreate`), the optional A/B dummy allocation, the two A/B ring allocations, and the direct teardown free sites listed above. No other production `mttFree()` call exists in the two source files. UAR has no dynamic alloc/free API in this implementation; the shared runtime index and BAR2 MMIO mapping are the resource/lifetime boundary.
- Offline regressions cover EQ `.105`, CQ `.106`, RQ/SQ `.107` create-time MTT refusal owner reachability and A/B `.109` ring-owner retry. The 28-script `.109` suite and isolated complete build pass (kext SHA-256 `1fe7399f7527bebea16c81711950f4c03a1d317289a0b72cf352fac2f5b4600f`); synthetic/source-contract checks do not prove real IOKit or hardware semantics.
- Next code slice: close all production release-site behavior gaps and audit late BAR2/doorbell callers against stop and IRQ/workloop lifetimes; design/test release credentials covering DMA, CPU callbacks, IRQ and reset-domain scope. Require a successful normal release path plus failure paths that preserve metadata and perform zero unsafe frees.
- A successful `HW2SW_*` or QP-to-RST reply is currently treated as the queue-level normal-return condition; this inventory does not independently prove DMA stopped, CPU/IRQ callbacks drained, or full PCI reset-domain scope. Keep R02/R03/R06 and hardware acceptance open.
