## 1. 目标与完成定义

2026-10-23增量：0.44.90将FLR改为macOS公开平台事务，失败不再读设备，成功也
不使用旧MMIO或归还owner。32组离线回归及构建exit0，65条live/tar清单和两个
binary一致；未上机。只完成平台调用切片，不替代代次/scope、CPU排空、DMA
静止及真正恢复验收；P0/P1与全功能完成定义不变。

0.44.91补平台调用前的配置底账检查（身份有效、BAR已分配、Command可读且memory
decode开启），4个损坏输入反例由12项失败转为96场景552检查通过。32组回归/构建、
65条manifest与二进制核验通过；仍是离线工作，不改变P0/P1验收状态。

目标：将本机 ConnectX-3 Pro 的**实际硬件/固件支持能力**在 macOS 上安全、稳定、可维护地开放，并逐项端到端验收F01–F44及后续发现的适用能力。
用户已确认：**系统原生网络优先；macOS 无通用接口的专有能力，接受配套用户态 SDK/工具**。

“完美适配”是验收目标，不是已经证明的可行性结论。以下约束不能偷换：

- 硬件支持 ≠ 固件当前开放 ≠ 驱动已实现 ≠ 应用可用 ≠ 已验收。
- 平台缺接口、缺对端/交换机、缺授权，记为阻塞；不能借此标为完成或硬件不适用。
- 确证本卡不支持的功能才允许 `N/A-HW`。平台无法实现的功能保留 `BLOCKED-PLATFORM`；如要降低总目标，须用户另行确认。
- “所有功能”以[能力矩阵](CX3-PRO-CAPABILITY-MATRIX.md)为最低清单；P0 必须把本卡原始 capability 的每个特性位、数量、端口属性映射到台账，发现遗漏即新增条目，不能因清单没写就排除。
- 芯片家族中的其他 SKU、其他 GPU/主板功能不是本卡能力；不能以营销词推断本卡支持。
- 首个正式支持组合是**这张卡 + 本机 x86_64 + 实测 macOS 构建**。其他 macOS 版本、Apple Silicon、其他 OEM 固件分别建兼容性验收，不能由单机结果外推。

三种不同交付名称：

| 交付 | 必须成立 | 不代表什么 |
| --- | --- | --- |
| 基础联网原型（已有 M4） | 已有证据证明普通模式下协议栈收发 | 不代表稳定日用、满速、全功能 |
| 稳定日用以太网版 | P0–P4 的网络/稳定性门全部通过，适用项零未决 | 不代表 RDMA、IB、虚拟化等已完成 |
| 全功能适配版 | P0–P8 适用子项全部 PASS，未知项清零；硬件不适用逐项有依据 | 任一平台或外设阻塞仍存在时不得使用这个名称 |

完整性判定按子项，不把一个族的某个样例通过当全族通过。不提供无依据的“完成百分比”或固定工期。

- **原生网络适配器**：优先现有 IOKit/IONetworkingFamily，提供每口接口、媒体、MTU、过滤与网络卸载；仅使用匹配运行系统 ABI 的接口。
- **受控会话/控制面**：初始化与重配置只有一个写入者，显式状态机、阶段编号、超时和审计。自动化不能绕过安全门。
- **用户态 SDK/工具**：capability 查询、时间戳、RDMA verbs/CM、必要管理面；具备版本协商、句柄隔离、权限、进程退出回收和示例。不是向普通应用裸露物理内存或任意 BAR 写。
- **验证/观测面**：每项版本身份、原始命令/读数、远端抓包、计数增量和故障现场。告警通道独立于被测 CX3 数据链路。

保留当前 `start()` 不发固件命令/不启 DMA 的构建保证。自动开机启用先决策，再通过受控用户态服务等候选路径实现；不能直接把手工初始化链搬入 `start()`。
DriverKit 是待评估备选，不是预先决定的重写工程，也不是默认能补齐 RDMA、RSS、VF 或签名权限的万能接口。

### 4.1 当前P0/P1的推进顺序（v3；取代旧版续跑顺序）

1. **停止重复已完成工作**：不再补 .59 证据或重复 R01；当前离线入口为 batch54/.99-local，文件只作状态快照，不代表硬件候选。
2. **有限安全审计包**：一次完成本轮候选可达路径的 owner/reuse/释放点清单，并标明未来尚未接入功能的不可达证明；据清单补真实生产释放点的正反向测试。R02/R03/R06 仍须保持 PARTIAL，直到对应安全合同真实闭环。
3. **并行离线推进**：R04 的运行身份/导出消费链、R05 的精确缺项与查询副作用审查，以及 D04/D05 的独立规格、用户态/文档/许可工作可并行；不得把一个总体状态 BLOCKED 当成所有子项的阻塞。
4. **实验包先行审查**：硬件实验只依赖该实验涉及的安全不变量和 T04 门禁，不要求最终 P1-S 全部通过；但实验可达路径、停止/恢复、独立管理、通知回执和当轮暂停窗口必须齐全。严禁由计划文本自动授权安装、启动、复位或重启。
5. **有证据地合流与晋级**：先在获准实验中重证基线/必要安全退出，再按门禁扩展到正常重开、RSS 对照。P1-S 决定安全日用路径，P1-R 单独决定多队列；只把相应已验收子项晋级，不等于 P2–P8 整体完成。

安全模型补充：正常资源撤销和异常 reset 后的隔离/回收是两种证明义务。正常撤销可按对象/依赖验证其硬件停止与 CPU 引用排空；异常复位还需身份、代次、reset scope、DMA 与回调静止证据。任何一种证明不成立时保留内存并拒绝复用，不能靠释放压力降低安全要求。

一次小实验可以依赖同一候选中已审查的安全不变量，不以“P1全部完成”制造循环依赖。各实验仍需单独写明允许操作、验收、停止和恢复；版本升级、重复构建、增加测试数量本身不构成阶段进展。

关键顺序修正：

- **TSO 不依赖 jumbo**：可将大 TCP 段分割成标准 MTU 帧；需要正确 TX 元数据/分段/DMA/回收，不能用大 ping 验 TSO。
- MTU/环/端口模式等重配置须先证明 quiesce → 停 DMA/IRQ → 有序撤销 → 重建 → 发布的事务性；哪些设置确需停口以硬件语义为准，不能一概要求复位。
- **RSS 入口的特殊 QPC 读回问题先于多队列验收**；不能仅把现有 QUALIFIED 改为 PASS。
- 先验证公开 KPI 下的驱动内部多硬件队列、锁/向量/流映射，再决定是否有必要迁移架构；不要把 AVB 队列当 RSS 队列。

## 5. 共同验收契约

以下是本计划提出的最低实验目标；P0 用实际资源核定具体命令与基准，不能因资源不足静默降低。

### 5.1 正确性与稳定性

- 每次硬件实验记录 macOS build、boot、卡/端口身份、运行 UUID/hash、工具 ABI、开关、拓扑、cap 快照与前后计数；接口按 MAC/PCI/端口映射，不硬编码 en2 永远正确。
- 每口 IPv4/IPv6、DHCP/静态、ARP/ND、标准 MTU、支持的 jumbo 边界、TCP/UDP 双向、组播/广播/过滤；显式绑定接口，保留远端 pcap。
- 最低循环目标：冷启动10、暖重启20、sleep/wake50、链路 down/up100、接口 stop/reopen100；都检查资源和后台设备。系统本身不支持的睡眠形态先跑无 CX3 基线，平台失败不算驱动通过。
- 日用版至少48小时混合负载；全功能候选至少72小时组合 soak，含双口、网络+RDMA/适用高级功能、空闲/高负载交替、内存压力、客户端异常退出。零 panic/冻屏/不可恢复 stall，资源占用无持续泄漏；具体流量与告警日志必须随报告保存。
- 若历史冻屏不能确定单一根因：至少将全部已知触发场景、候选因果与排除证据入账，关闭可复现安全缺陷并完成压力/故障注入。只允许注明“原触发场景未再现，历史归因未定”，不得宣布已定位/根治；未解决的可复现卡死阻止发版。

### 5.2 性能与功能归因

- 同卡同拓扑 Linux 参考，macOS 分别测单口/双口、单流/多流、大包/小包、双向、CPU、p50/p99 延迟、重传与丢包。
- 大流吞吐目标先取**同条件 Linux 参考的90%**；同时给出绝对 Gb/s 与实际 PCIe/速率预算。调整目标须记录瓶颈证据和用户确认，不能用“线速”掩盖 PCIe x4 限制。
- TSO 用大 TCP write + 明确开关 A/B + TX WQE/计数 + 对端线上分段；大 ping 只测 MTU。校验和以对端线包为准，避免本机抓包的 offload 假坏包。
- RSS 用可控五元组、每队列 CQ/帧计数、hash/indirection 测试向量和流内次序；吞吐提高本身不证明 RSS。IRQ 验收含空闲不忙轮询、CQ 再 arm 无丢唤醒、中断风暴与安全回退。
- 时间能力分开记录：硬件 RX/TX timestamp、时钟读取/调整、PTP 同步误差与漂移、macOS gPTP/AVB 集成。不能从 timestamp 支持推断完整 TSN/定时发送。
- 低延迟/小包/PTP 的数值目标，在 P0 取得同条件参考后写入具体规格；未定义或未测量不能验收。

### 5.3 安全、恢复与可运维性

- 不以固定延时替代 DMA 已停止的证明；先阻断新提交，再撤销 IRQ/回调与硬件访问，最后释放映射内存。命令超时/复位失败时优先隔离和保留仍可能被 DMA 使用的内存，禁止冒险释放。
- CQ/WQE 16位序号回绕、环索引、长度溢出、owner/phase、重复完成、畸形 CQE、错误 QPN、部分分配失败、并发 close/reset 都有离线回归和独立硬件验证边界。
- SDK 每进程 PD/句柄权限、MR lifetime、fork/exec/退出、失效 rkey/lkey、越界访问、资源配额、取消/事件队列均纳入测试；无隔离证明不得开放不受信应用。
- 冻屏探针与 ntfy 演练须在每次危险测试前有实际回执；手机曾“收到但不弹窗”，不能把投递成功当即时提醒可靠。告警走管理接口/独立远端观察者；恢复盘与禁用开关可用；用户忙碌时不自行安排危险复现或重启。
- 签名、SIP/启动安全策略、Apple entitlement 能否获批分别给出现实结果；不能把开发机可加载称为可在所有 Mac 默认安装。禁止扩大 SIP 放宽范围来掩盖设计缺陷。
